## GitHub Vocabulary
### **Commit:**  
A commit is like saving a snapshot of your project at a specific point in time. It records what changed so you can track progress and go back if needed.

### **Commit Message:**  
A commit message is a short note you write when saving a commit. It explains what changes were made, similar to adding a comment when saving a new version of a document.

### **Commit IDs:**  
A commit ID is a unique code automatically assigned to each commit. It helps you identify and refer to specific changes, like a version number or tracking code.

### **History Tool:**  
The history tool in GitHub lets you view a detailed, chronological list of all changes made to a file or project. It shows what was changed, who made each change, and when.

### **Blame Tool:**  
Blame is a tool that shows who last changed each line in a file. It helps you find out who to ask about specific changes, like seeing who edited a paragraph in a shared document.

### **Issues:**  
Issues are like digital sticky notes for tracking tasks, bugs, or ideas. They help teams organize work, report problems, and discuss solutions in one place.

### **Reviewers:**  
Reviewers are team members who are asked to look over changes before they are finalized, including testing new code and editing documentation.

### **Assignees:**  
Assignees are the people responsible for making sure the review process goes smoothly and is often someone in a team lead or code integrator role.  They may check that the right people are assigned as reviewers, that reviews are completed in a timely manner and they may be in charge of all merges.
